# 家庭点菜小程序 — 产品设计文档

> 版本：v1.0  
> 日期：2026-08-15  
> 状态：设计评审中

---

## 一、产品概述

### 1.1 产品定位

一款面向家庭内部使用的微信小程序，解决"今天吃什么"的日常沟通问题。家庭成员（掌勺的和等饭的）通过小程序共享菜品库、实时点菜，掌勺的根据点菜情况买菜做饭。

**不是商业化点单系统**——没有支付、没有价格、没有配送，纯粹是家人之间"今晚想吃啥"的轻量协作工具。

### 1.2 核心场景

姐姐下班前，在小程序里看一眼弟弟和爸妈今天点了哪些菜，心里有数后直接去菜市场买菜。弟弟在公司摸鱼时打开小程序，从菜品库里点几道想吃的菜，姐姐那边实时收到通知。

### 1.3 设计原则

- **极简操作**：3步以内完成点菜，不增加家人的使用负担
- **温馨平等**：身份命名幽默但没有贵贱之分
- **实时同步**：点菜即所见，家人之间无需反复确认
- **零运维成本**：基于微信云开发，无需服务器，免费额度内运行

## 二、角色定义

| 角色 | 代号 | 权限 |
|------|------|------|
| 掌勺的 | chef | 菜品库增删改查、临时隐藏菜品、撤下任意菜品的点菜、管理家庭成员 |
| 等饭的 | eater | 浏览菜品、点菜/取消自己的点菜、查看谁点了什么 |

**身份规则：**
- 身份按家庭独立设置，同一用户在不同家庭可以有不同身份
- 每个家庭中两种身份的数量不限
- 用户可在"我的"页面随时切换当前家庭的身份
- 家庭最多10人

## 三、功能清单

### 3.1 账号与登录

- 微信一键登录（wx.login + 云函数获取openid）
- 自动创建用户档案，获取微信昵称和头像
- 无需额外注册流程

### 3.2 家庭管理

- **创建家庭**：输入家庭名称，系统生成4位随机加入码和二维码
- **加入家庭**：
  - 方式A：输入4位数字加入码（面对面建群）
  - 方式B：扫描家庭二维码
- **多家庭切换**：一个用户可加入多个家庭，顶部切换当前家庭
- **成员管理**：查看成员列表、成员身份、移除成员（仅掌勺的）
- 人数上限：每个家庭最多10人

### 3.3 菜品库管理（仅掌勺的）

- **菜品字段**：菜名、分类（荤菜/素菜/汤品/主食/凉菜）、图片、是否隐藏、累计上架次数
- **添加菜品**：输入菜名、选择分类、可选上传图片（不上传则使用分类占位图）
- **编辑菜品**：修改菜名/分类、上传或更换图片
- **删除菜品**：从菜品库中永久移除
- **临时隐藏**：某道菜今天做不了，暂时隐藏（次日自动恢复），不删除菜品
- **自动入库**：添加新菜时自动存入菜品库，无需额外操作

### 3.4 菜品图片

- **自定义上传**：掌勺的可拍照或从相册选择菜品图片
- **AI分类占位图**：未上传图片时，根据菜品分类自动匹配预设插画（荤菜/素菜/汤品/主食/凉菜各一张）
- **图片存储**：微信云存储，CDN加速访问
- **更新替换**：后期有了实拍图可随时上传替换占位图

### 3.5 今日点菜

- 菜品库即为今日菜单，无需"每日上架"操作
- 每道菜显示"我想吃"按钮和已点菜成员头像聚合
- **投票式点菜**：一道菜多人想吃只显示一条，聚合展示头像和人数
- 点击"我想吃"点菜，再次点击取消
- 已点过的菜按钮显示"已想吃"状态
- 等饭的只能取消自己点的菜
- 掌勺的可撤下任意菜品（食材不够等情况），撤下后通知点过该菜的人
- 菜品按点菜人数（热度）排序，无人点的排后面

### 3.6 点菜汇总

- 按热度排序展示今日所有被点的菜品
- 每道菜显示点菜成员列表
- 掌勺的可在此页面撤菜
- 空状态提示："今天还没有人点菜，快去点几道吧"

### 3.7 历史记录

- 每日凌晨0点自动归档当天点菜记录
- 可按日期查看历史点菜情况
- 历史记录只读，不可修改

### 3.8 实时同步

- 任何人点菜/取消，所有在线成员页面立即刷新
- 基于微信云开发数据库 `db.watch` 实现，无需自建WebSocket
- 离线时操作进入队列，恢复连接后自动同步

### 3.9 消息通知

- **点菜通知**：首次有人点某道菜时，向掌勺的发送微信订阅消息（"弟弟想吃红烧肉"）
- **撤菜通知**：掌勺的撤下某道菜时，向点过该菜的成员发送订阅消息
- 同一道菜后续加人不再重复通知，避免刷屏
- 通知需用户首次使用时授权订阅消息权限

### 3.10 主题切换

- 默认跟随系统浅色/深色模式
- 支持手动切换：浅色 / 深色
- 支持强调色切换：蓝（默认）/ 绿 / 橙 / 粉
- 深色模式采用OLED纯黑背景
- 主题偏好保存在用户档案中，跨设备同步

## 六、系统架构

### 6.1 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端 | 微信小程序原生（WXML/WXSS/JS） | 不引入第三方框架，轻量快速 |
| 后端 | 微信云开发云函数（Node.js） | 免运维，与小程序原生集成 |
| 数据库 | 云开发NoSQL文档数据库 | 内置db.watch实时推送 |
| 文件存储 | 云开发云存储 | 菜品图片 + 二维码 |
| 实时通信 | db.watch 数据监听 | 无需自建WebSocket |
| 消息推送 | 微信订阅消息 | 点菜/撤菜通知 |
| 定时任务 | 云函数定时触发器 | 每日0点归档 |

### 6.2 架构分层

```
┌─────────────────────────────────────────┐
│           微信小程序客户端                │
│  WXML/WXSS · JS逻辑 · db.watch · 图片上传 │
└───────────────────┬─────────────────────┘
                    │ wx.cloud.callFunction
                    ▼
┌─────────────────────────────────────────┐
│            云函数层（Node.js）            │
│  login · family · dish · vote           │
│  notify · dailyReset                    │
└───────────────────┬─────────────────────┘
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
┌──────────┐ ┌──────────┐ ┌──────────┐
│ 云数据库  │ │ 云存储    │ │ 定时触发器│
│ NoSQL    │ │ 图片/CDN │ │ 每日归档  │
│ db.watch │ └──────────┘ └──────────┘
└──────────┘
```

### 6.3 云函数清单

| 云函数 | 功能 | 主要操作 |
|--------|------|----------|
| login | 用户登录 | wx.login获取openid，创建/更新users记录 |
| family | 家庭管理 | 创建家庭、加入家庭、切换家庭、获取家庭列表、移除成员 |
| dish | 菜品管理 | 菜品CRUD、隐藏/恢复、图片上传签名 |
| vote | 点菜管理 | 点菜、取消点菜、掌勺的撤菜、获取当日点菜列表 |
| notify | 消息通知 | 发送订阅消息（点菜通知、撤菜通知） |
| dailyReset | 每日重置 | 定时触发，归档daily_votes到vote_history，重置isHidden |

### 6.4 安全规则

云数据库权限设置：
- **users**：仅创建者可读写自己的记录
- **families**：所有用户可读，仅创建者可修改
- **family_members**：家庭成员可读，加入/退出通过云函数
- **dishes**：家庭成员可读，仅chef角色可写（云函数校验）
- **daily_votes**：家庭成员可读，点菜/取消通过云函数校验权限
- **vote_history**：家庭成员只读

所有写操作通过云函数执行，云函数内校验用户身份和权限，客户端不直接操作数据库写入。

## 七、核心业务流程

### 7.1 用户首次使用流程

1. 打开小程序 → wx.login自动获取openid
2. 查询users集合，无记录则自动创建
3. 查询family_members，判断是否已加入家庭
4. 未加入 → 欢迎页（创建家庭 / 加入家庭）
5. 加入/创建成功 → 身份选择页（掌勺的 / 等饭的）
6. 选择身份 → 进入今日点菜主页

### 7.2 加入家庭流程

```
掌勺的创建家庭 → 输入家庭名 → 生成4位加入码+二维码
                                              │
等饭的选择加入方式 ──────────────────────────┤
                    │                         │
            输入4位码                    扫描二维码
                    │                         │
                    └──────────┬──────────────┘
                               ▼
                    云函数family.join校验：
                    · joinCode/familyId是否有效
                    · 家庭成员数是否<10
                    · 是否已在家庭中
                               │
                    加入成功 → 选择身份 → 进入主页
```

### 7.3 点菜流程

```
用户点击"我想吃"
       │
       ▼
云函数vote.add：
  · 校验用户是家庭成员
  · 校验菜品未被隐藏
  · 校验今天未点过该菜（幂等）
  · 写入daily_votes
       │
       ├──→ db.watch自动推送 → 所有家庭成员UI实时刷新
       │
       └──→ 若是该菜品今天第一票 → notify云函数 → 订阅消息通知掌勺的
```

### 7.4 取消点菜流程

```
用户点击"已想吃"（取消自己的点菜）
       │
       ▼
云函数vote.cancel：
  · 校验是本人的点菜记录
  · 删除daily_votes记录
       │
       └──→ db.watch自动推送 → 所有人UI刷新
```

### 7.5 掌勺的撤菜流程

```
掌勺的在汇总页点击"撤下这道菜"
       │
       ▼
云函数vote.chefCancel：
  · 校验用户role === chef
  · 删除该菜品当天所有daily_votes记录
  · 设置dishes.isHidden = true
       │
       ├──→ db.watch自动推送 → 所有人UI刷新（菜品消失）
       │
       └──→ notify云函数 → 订阅消息通知所有点过该菜的人
```

### 7.6 每日重置流程

```
每日 00:00 定时触发器
       │
       ▼
云函数dailyReset：
  · 查询所有家庭昨天的daily_votes
  · 批量写入vote_history（冗余菜名和昵称）
  · 删除daily_votes中昨天的数据
  · 将所有dishes.isHidden重置为false
  · 完成
```

## 八、UI设计规范

### 8.1 设计风格

遵循 Apple Human Interface Guidelines，整体风格简洁、克制、高级。

### 8.2 色彩系统

**浅色模式：**

| 用途 | 色值 | 说明 |
|------|------|------|
| 主色（蓝） | #007AFF | 按钮、链接、选中态 |
| 主文字 | #1D1D1F | 标题、正文 |
| 次文字 | #86868B | 辅助说明、时间戳 |
| 三级文字 | #C7C7CC | 占位符、空状态 |
| 背景 | #FFFFFF | 页面背景 |
| 卡片背景 | #F5F5F7 | 列表卡片、分组背景 |
| 分隔线 | #E5E5EA | 边框、分割线 |
| 成功绿 | #34C759 | 成功状态 |
| 警告橙 | #FF9500 | 提示、待处理 |
| 错误红 | #FF3B30 | 删除、错误 |
| 紫 | #AF52DE | 特殊标记 |

**深色模式：**

| 用途 | 色值 |
|------|------|
| 背景 | #000000（OLED纯黑） |
| 卡片背景 | #1C1C1E |
| 主文字 | #FFFFFF |
| 次文字 | #98989D |
| 分隔线 | #38383A |

**强调色可选：** 蓝 #007AFF（默认）/ 绿 #34C759 / 橙 #FF9500 / 粉 #FF2D55

### 8.3 字体

- 中文：苹方（PingFang SC）
- 英文/数字：SF Pro Text / SF Pro Display
- 标题：28px / 700 weight / -0.5px letter-spacing
- 正文：16px / 400 weight
- 辅助文字：12-14px / 400 weight
- 按钮文字：15-17px / 600 weight

### 8.4 圆角与间距

- 卡片圆角：16px
- 按钮圆角：20px（胶囊形）
- 头像圆角：50%（圆形）
- 菜品图标圆角：14px
- 页面水平边距：16-20px
- 卡片间距：10px
- 卡片内边距：14px

### 8.5 阴影

- 卡片：0 1px 3px rgba(0,0,0,0.06)
- 浮层/弹框：0 4px 24px rgba(0,0,0,0.12)
- 深色模式下减弱或移除阴影，改用边框区分

### 8.6 核心组件

**菜品卡片：**
- 左侧：52x52px圆角图标（emoji或菜品图片）
- 中间：菜名（16px/600）+ 点菜成员头像组（重叠圆形头像）
- 右侧：状态按钮（蓝色填充"已想吃" / 蓝色描边"我想吃" / 灰色"+想吃"）
- 背景：#F5F5F7，圆角16px

**底部Tab栏：**

## 九、技术要点

### 9.1 实时数据同步

使用云开发数据库的 `db.watch` 实现实时推送：

```javascript
// 监听当日点菜变化
const watcher = db.collection('daily_votes')
  .where({ familyId: currentFamilyId, date: today })
  .watch({
    onChange: snapshot => {
      // 更新UI
      this.setData({ votes: snapshot.docs });
    },
    onError: err => console.error(err)
  });
```

页面卸载时关闭watcher：`watcher.close()`

### 9.2 订阅消息

- 用户首次点菜时弹出订阅授权
- 使用微信一次性订阅消息，每次点菜可订阅一次
- 云函数调用 `openapi.subscribeMessage.send` 发送
- 消息模板："XX想吃XX" / "XX菜已被掌勺的撤下"

### 9.3 图片处理

- 上传前客户端压缩（wx.compressImage，质量80%）
- 上传至云存储，存储路径：`dishes/{familyId}/{dishId}.jpg`
- 菜品列表使用云存储临时链接
- 分类占位图打包在小程序本地（assets/images/categories/）

### 9.4 二维码生成

- 创建家庭时云函数调用 `openapi.wxacode.getUnlimited` 生成小程序码
- 场景值携带familyId
- 小程序码图片存储至云存储
- 扫码进入时通过 `options.scene` 解析familyId

### 9.5 性能优化

- 菜品列表分页加载（每页20条）
- 菜品图片使用懒加载（lazy-load）
- db.watch只监听必要字段和当日数据
- 历史记录按日期索引查询
- 云函数冷启动优化：减少依赖包体积
