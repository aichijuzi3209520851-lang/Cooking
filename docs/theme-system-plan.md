# 主题系统重构方案（待评审）

> 背景：用户反馈主题切换"只有深浅色有变化，其他配色看不到任何变化"。诊断后确认：**这不是感知问题，是功能从未生效过**。本文档给出根因分析、大厂参考、三套候选方案与推荐设计，**待选型后实施**。

---

## 1. 现状诊断：主题功能三个根因

### R1（致命）CSS 选择器错位 —— 主题功能整体失效

- `theme.js` 把主题 class 计算后传给页面，页面挂在**根 `<view>`** 上：
  `<view class="container menu-page {{themeClass}}">`
- 但 app.wxss 里所有主题选择器都写成了 **`page.theme-dark` / `page.accent-xxx`**——这种选择器要求 class 挂在 `page` 元素上，而 `page` 元素上**从来没有 class**。
- **后果**：手动深色、手动浅色、全部 4 个强调色（辣椒红/焦糖橙/姜黄/葱青）**从上线起就全是死代码**。
- 用户看到"深浅色有点变化"的真相：跟随系统时 `@media (prefers-color-scheme)` 媒体查询生效（不依赖 class）；手动切换时只有 JS 设置的**导航栏颜色**变了，内容区纹丝不动。
- 诚实说明：此前 UI 审查批次① 我补的 `page.theme-light` 也犯了同样的选择器错误，同样不生效，需一并修正。

### R2 tabBar / 窗口底色不随强调色

`theme.js` 中 tabBar 选中色硬编码（浅 `#D93A2B` / 深 `#E8564A`），与 accentColor 无关。即使选择器修好，强调色也永远不会出现在最显眼的位置。

### R3 设置页零预览、零感知

主题设置页本身几乎没有强调色可变元素（只有选中圈描边），点击强调色后页面几乎无变化，也没有任何预览卡片，用户无从感知"到底改了什么"。

## 2. 大厂与开源参考

| 产品 | 主题做法 | 可借鉴点 |
|------|----------|----------|
| 微信 | 浅色 / 深色 / 跟随系统，**无强调色** | 极简三选项是国民级默认形态 |
| 支付宝 / 淘宝 / 小红书 | 跟随系统深浅色 | 跟随系统为第一选项 |
| 哔哩哔哩 | 简洁白 / 夜间 + 跟随系统 | **主题卡片选择器**（每项带预览色卡） |
| Telegram | 日间主题 × 强调色自由组合 | 强调色玩法上限，但设置复杂、工具属性强 |
| Vant Weapp（18.4k★） | CSS 变量 + class 换肤 | 与本项目现有架构同构，证明路线正确 |

**共性结论**：
1. 主流做法是「**少数几套完整配色**」（每套含背景/卡片/文字/强调色/tabBar），而不是「明暗 × 强调色」的矩阵——矩阵需要用户自己搭配，心智负担大；
2. 主题设置页**必须所见即所得**（色卡预览，点完立刻变）；
3. 强调色只有效率工具类产品暴露给用户，餐饮/生活类几乎不暴露。

## 4. 候选方案

### 方案一：主题家族制（推荐）

设置页改为 **4 张主题卡片**：`跟随系统` / `温馨暖调` / `清新绿意` / `静谧夜间`。每张卡片是一个 mini 预览（背景块 + 强调按钮块 + 文字线），点击立即生效，所见即所得。

- 「跟随系统」：系统浅色 → 温馨暖调；系统深色 → 静谧夜间；监听 `wx.onThemeChange` 实时切换（现在切系统主题要重进页面才生效，也一并修掉）
- **废除强调色选择器**——它的职责被三套完整配色取代（清新绿意本质上就是原来的"葱青强调色"扩展成的完整主题）
- 存量用户迁移：`theme:'dark'` → 夜间；其余 → 跟随系统；`accentColor` 字段忽略并清掉

**优点**：对齐大厂心智、正好顺势修掉 R1 致命 bug、设置页体验质变、状态空间最简（4 选项）。
**缺点**：删掉一个已发布的设置项（但其从未生效过，用户无损失）。

### 方案二：只修 bug，保留「明暗 × 强调色」

选择器 `page.xxx` → `.xxx`（R1 修复）、tabBar 跟随强调色（R2）、设置页加预览（R3）。

**优点**：改动最小。**缺点**：修好了用户也感知平平（强调色覆盖面就那几个元素），不满足"三类配色"的诉求，不推荐单做。

### 方案三：家族 × 家族内强调色（温馨：红/橙/金；清新：绿/青；夜间：固定）

**优点**：最灵活。**缺点**：状态组合多、设置页复杂、与"大厂都不开强调色"的共识相悖。建议作为二期可选，首期不做。

### 对比总表

| | 方案一 家族制 | 方案二 只修bug | 方案三 家族×强调色 |
|---|---|---|---|
| 满足"三类配色"诉求 | ✅ | ❌ | ✅ |
| 修复 R1 致命 bug | ✅ | ✅ | ✅ |
| 设置页体验 | 质变（色卡预览） | 小修 | 复杂 |
| 状态复杂度 | 4 选项 | 3×4 矩阵 | 3 家族×2-3 |
| 与大厂惯例一致 | ✅✅ | 一般 | 一般 |
| 工作量 | 1~1.5 天 | 0.5 天 | 2 天+ |

## 5. 推荐方案（一）技术设计

### 5.1 数据与迁移

```js
// app.globalData.themeFamily: 'system' | 'warm' | 'fresh' | 'dark'
// storage 迁移：theme==='dark' → 'dark'；其余 → 'system'；accentColor 清除
```

### 5.2 theme.js 重构要点

```js
const FAMILIES = {
  warm:  { navBg:'#FAF6F0', tabBg:'#FFFFFF', tabSelected:'#D93A2B', windowBg:'#FFFDF9', bgText:'dark' },
  fresh: { navBg:'#F0F7F1', tabBg:'#FFFFFF', tabSelected:'#2F9E6E', windowBg:'#FBFDF9', bgText:'dark' },
  dark:  { navBg:'#201B16', tabBg:'#201B16', tabSelected:'#E8564A', windowBg:'#17130F', bgText:'light' }
};
// resolveFamily(): system → 系统深色 ? dark : warm；其余原样
// applyTheme(): themeClass = 'theme-warm'|'theme-fresh'|'theme-dark'（system 模式下实时解析）
// 新增 wx.onThemeChange（app 级注册）：跟随系统时系统切换主题实时刷新当前页面
```

### 5.3 CSS 侧（关键修复）

```css
/* 关键修复：去掉 page. 前缀——主题 class 实际挂在页面根 view 上 */
.theme-warm  { /* = 现有亮色令牌（默认即温馨，此块主要用于 system 模式从夜间切回） */ }
.theme-fresh { /* §3.2 清新绿意全套令牌 */ }
.theme-dark  { /* §3.3 夜间全套令牌（现有内容迁入） */ }
/* @media (prefers-color-scheme: dark) 保留：仅在 themeFamily==='system' 时
   由 theme.js 决定是否挂 theme-dark class，媒体查询本身不再自动生效
   （否则"跟随系统=浅色"在系统深色下会错乱）→ 需把现有媒体查询段删除或改造 */
```

> 注意：改造后媒体查询与手动 class 的双轨制简化为**单轨 class 制**（由 theme.js 统一决策），`theme-light`/`page.theme-*`/`page.accent-*` 全部清理。这比双轨更可控，也彻底消灭 R1 这类"class 挂错地方"的隐患。

### 5.4 设置页重设计（体验质变）

```
┌────────────────────────────┐
│  外观                        │
│  ┌─────────┐ ┌─────────┐   │
│  │ ▒▒▒预览▒ │ │ ▒▒▒预览▒ │   │
│  │ ●按钮 文字│ │ ●按钮 文字│   │
│  │ 跟随系统  │ │ 温馨暖调  │   │
│  └─────────┘ └─────────┘   │
│  ┌─────────┐ ┌─────────┐   │
│  │  预览    │ │  预览    │   │
│  │ 清新绿意 │ │ 静谧夜间  │   │
│  └─────────┘ └─────────┘   │
│  跟随系统卡副标题：「当前：温馨暖调」│
└────────────────────────────┘
```

- 每张卡片用纯 CSS 绘制 mini 预览（背景块 + 圆角按钮块 + 两行文字线），选中卡带 accent 描边 + ✓
- 点击立即生效（当前页预览元素全部染色，天然所见即所得）
- 「跟随系统」卡片副标题实时显示当前实际生效的主题

### 5.5 深色图片压暗等配套

现有 `--img-filter`、`--glow-*` 令牌机制不变，`theme-dark` 下行为照旧；清新主题无需压暗（`--img-filter: none`）。
