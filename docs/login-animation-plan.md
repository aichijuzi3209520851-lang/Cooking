# 登录页悬浮动效方案（待评审）

> 目标：为「今天吃啥」登录页加入类似参考项目（橘记 Juji）的图标悬浮漂浮动态效果。
> 状态：**方案对比与推荐，未实施**——等你选定方案后再动工。
> 约束：保持暖调家庭定位；不引入业务逻辑改动；控制包体积与低端安卓机性能。

---

## 1. 参考项目（橘记）逆向结论

克隆阅读了 `Juji---Manual-Expense-Tracker` 的登录页，其动效实现为**零依赖纯 CSS**：

```
WXML：8 个 <image> 绝对定位图标（SVG，opacity 0.68，pointer-events: none）
      + 2 个 .login-glow 光晕（blur 90rpx 的彩色圆）
WXSS：4 组 @keyframes（driftA/B/C/D，时长 9.8s/11.5s/10.2s/12.4s 错开）
      每组对 transform: translate3d(±10~34rpx) rotate(±2~6deg) 做 ease-in-out 无限循环
JS：  无任何动画代码
```

要点：只动 `transform`（GPU 合成层，不触发重排）、位移幅度小（±30rpx 级）、周期长（10s+）且错帧，观感是「轻轻漂」而不是「飞来飞去」。**这个骨架本身就很健康，值得沿用。**

## 2. 现有库调研（GitHub）

| 库 | 结论 |
|----|------|
| `wechat-miniprogram/lottie-miniprogram`（432★，微信官方组织维护） | 唯一值得考虑的动画库：在小程序 canvas 里播 Lottie JSON 动画。用于方案 B。 |
| `animate.wxss` 等 animate.css 移植 | 0★ 量级，无人维护，且都是"入场/过渡"类动效，做不了常驻漂浮，排除。 |
| 漂浮氛围动效类库 | **不存在主流库**——这类效果业内惯例就是手写 CSS（参考项目也是手写）。 |

结论：这类动效不需要引库；唯一的"库选项"是 Lottie，属于另一个重量级。

## 3. 候选方案

### 方案 A：纯 CSS 漂浮图标 + 渐变光晕（参考项目同构）⭐ 推荐

**A1（推荐先做）：漂浮物用项目既有分类 emoji**
- 图标：`🍖 🥬 🍲 🍚 🥗`（与菜单页菜品分类 emoji 完全一致）+ 2~3 个 accent/orange 色小圆点缀
- 优点：零图片资源、零包体积增量、与"菜品分类"体系呼应，看到图标就想到点菜，品牌心智最强
- 缺点：emoji 在不同机型渲染风格略有差异（iOS/安卓字体不同）；无法控制细节造型

**A2（升级档）：出 6~8 张暖色手绘风小图（SVG/PNG）**
- 优点：造型完全可控、风格最统一、显精致
- 缺点：需要出图资源（我可以先用 emoji 版落地，你后续随时换图，CSS 不用动——`<image>` 与 `<text>` 结构对等替换）

**实现规模**：WXML +10 行，WXSS +90 行，JS 0 行。分布沿用参考项目的"四角 + 两侧"策略，避开中央品牌区与登录卡片；深色模式下图标 opacity 降低、光晕换深色令牌。

**性能护栏**：
- 只动 `transform` + `opacity`（合成器路径，不触发布局/绘制）
- 光晕用 `radial-gradient` 而非参考项目的 `filter: blur(90rpx)`——渐变本身是软的，省掉一个在低端安卓上很贵的实时模糊
- 数量封顶 8 个，禁用 `will-change` 滥用（translate3d 已强制提层）

**代价**：无依赖、无包体积增量、首屏零额外请求。

### 方案 B：Lottie 动画（官方 `lottie-miniprogram`）

在登录页放一个透明 `<canvas type="2d">`，播放一段 Lottie JSON（LottieFiles 有大量 free 的烹饪/食物动画：锅铲翻炒、蒸汽上升、餐具漂浮等）。

- 优点：表现力天花板，可做"整段品牌动画"（如 logo 翻炒登场），动效质感最高
- 缺点：+约 50KB JS 库 +几十 KB 动画 JSON；多一个 canvas 渲染层；需要筛选风格匹配（暖调/手绘）且授权干净的素材；登录页首屏成本上升
- 适用判断：**如果只是"图标轻轻漂"，杀鸡用牛刀**；如果未来要做品牌级开场动画，再上不迟（可与 A 共存：A 做氛围，B 做主视觉）

### 方案 C：Canvas 2D 自绘粒子（蒸汽泡泡上浮）

自写 canvas 粒子系统：底部升起半透明"热气泡泡"，呼应"热腾腾开饭"的隐喻。

- 优点：意象最贴"有食欲"，独一无二
- 缺点：常驻 requestAnimationFrame 耗电，代码复杂度最高（100+ 行 JS），低端机掉帧风险，为登录页性价比最低
- 结论：不推荐作为主方案

### 方案 D：重力感应视差（增强项，非独立方案）

`wx.onAccelerometerChange` 让品牌徽章和漂浮图标随手机倾斜轻微反向位移（±10rpx）。

- 优点：高级感、"这 app 有心思"的第一印象
- 缺点：常驻传感器耗电（需 onShow 开/onHide 关 + 节流）、开发者工具模拟器看不出来、真机才有效果
- 结论：可作为 A 或 B 的**可选增强**，不建议首期做

## 5. 推荐结论

**主推方案 A1（emoji 漂浮 + 渐变光晕），预留 A2 升级位。**

理由：与参考项目同构、零依赖零体积、性能最安全，而且用项目自己的菜品分类 emoji（🍖🥬🍲🍚🥗）做漂浮物，动画本身就在讲"这个 app 是干什么的"——这是橘记用购物袋/购物车图标做不到的先天优势。落地后若你觉得 emoji 质感不够，只需替换资源文件即可升级 A2，CSS 骨架不变；将来要做品牌级开场动画再评估 Lottie（方案 B）。

## 6. 选定后的实施要点（供评审确认）

1. 漂浮物分布：四角 + 两侧共 7 个（左上 🍖、右上 🥬、左中 🍚、右中 🥗、左下 🍲、右下两个色点），全部避开标题/卡片文字区
2. 动效参数沿用参考骨架：4 组 keyframes、9.5~13s、`translate3d ±14~34rpx`、`rotate ±5deg`、`ease-in-out infinite`、负 delay 错帧
3. 光晕 2 个：cream 色（左上）+ accent-soft 色（右下），`radial-gradient` 实现
4. 深色模式：图标 opacity 0.5、光晕换深色令牌色
5. 全部 `pointer-events: none`，纯装饰不挡任何点击
6. 验收：开发者工具 + 真机（含低端安卓）流畅 60fps；深浅两主题检查；375px 与大屏分布不叠字
